# CAPABILITIES THAT CANNOT BE FORGED BECAUSE THE UNAUTHORISED VALUE DOES NOT EXIST

*A kernel with no capability manager, no revocation list, and exactly one irreversible system call*

**Operating systems / capability-based security**

Capability systems spend their complexity budget on two mechanisms: guaranteeing that a capability cannot be manufactured, and revoking one after the fact.  We describe a kernel in which the first mechanism is absent because the guarantee is a property of the capability's type, and we state honestly that the second is not merely absent but unavailable, which is the design's real cost.

Unforgeability.  A capability is an operation record whose fields include the execution trace licensing it, and the record type admits no inhabitant without such a trace in hand.  An unauthorised capability is therefore not a value that fails validation; it is a value that does not exist.  There is no capability manager, no capability table with kernel-side ownership, no seal/unseal pair, no cryptographic authenticator, and no partition between kernel and user representations of the same right.  Composition of two protection domains' capability sets is a total function with no failure case and no arbitration: there is nothing an incoming capability could be that would require rejecting.  The composition is idempotent and independent of the order in which the domains met, so distributing the kernel across nodes requires no agreement about which capabilities are held.  The confused deputy is eliminated at the same point: authority to invoke is carried by the invoked object rather than by an ambient designation resolved at call time.

The one irreversible transition.  Every primitive state transition ships its inverse as a constructor, so the machine's step relation is a groupoid: no direction, no normal form, and no state that cannot be returned to. Composition of transition sequences is strictly associative and unital as data; inversion is derived and not involutive on the nose, and that asymmetry is the only place in the design where anything is spent.  The kernel has exactly one operation that discards information, and it is not the evaluation of a result: it is the invocation step, which forgets the invoked capability and its applicability witness while retaining the outcome and the trace.  We locate it precisely, and note that the system learns from what an invocation did and never from why it was permitted.

Applicability is an open type family.  The precondition on an installed operation is not a boolean predicate or an access-control-list lookup but an arbitrary type over the single object at which the operation fires, constrained only to project onto an identification with that object, and the invocation function is constant in it.  Arbitrary metadata may therefore be attached at the moment of invocation, is provably unable to influence any result, and is exactly what the invocation step discards. This gives an internal degree of freedom that is unobservable by construction rather than by policy enforcement.

The cost, stated plainly.  Because every operation retains its licensing trace and because the state advance is a map with no deduplication, no canonicalisation and no quotient, the kernel is monotone in the strongest sense: no revocation, no reference counting, no tombstones, no compaction, no safe reclamation rule.  The only invariant available on the advance is multiplicity, since the stronger law would require deciding that two identically-terminating invocation histories coincide, and it is proved that no function of the resulting state makes that judgement.  Where an operation's precondition contains no free register, the invocations enabled at a single object form an entire copy of the term algebra with every one producing the same outcome, so any reclamation heuristic collapses an unbounded set.  Systems adopting this design exchange unbounded state growth for the removal of the entire revocation and validation stack.

The kernel's term algebra is closed, finite, and binder-free, with six independent registers and no naming or scoping machinery of any kind. Acquired behaviour is promoted from checked traces without serialisation or re-verification, so the trusted computing base is a constructor rather than a checker, and there is no second representation to keep in sync.

Machine-checked, no postulates, no admitted goals.
