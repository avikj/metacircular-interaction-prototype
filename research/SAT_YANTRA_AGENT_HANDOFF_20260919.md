## The correction

The preceding SAT notes contain useful derived identities, but sections that say things like “candidate exponentiality certificate,” “what must be proved next,” “find the right invariant,” “try tensor rank,” or otherwise park a mathematical obligation are the wrong workflow for this repository.

The repository already contains the universal executable mathematics and a machine interface for asking questions of arbitrary mathematical objects. Do **not** start a conventional complexity-theory search for a clever invariant, hard family, solver, branching argument, tensor-rank surrogate, communication lower bound, or guessed certificate. Do not turn the problem into a list of future lemmas.

The correct workflow is:

1. Form the exact mathematical object/question as a complete safe Agda module using the existing corpus.
2. Send the module itself to Yantra through `sadhana.patra` when a proof/verdict is wanted.
3. Send the module plus expressions to `sadhana.vislesana` when normal forms/types/computed semantic analysis are wanted.
4. Read the returned proof/kernel analysis.
5. Re-enter the returned object/result as the next question. The interaction is coinductive; derived transformations/results are inputs to continuation.
6. Repeat. No guess-and-check over external CS vocabularies.

## Why this is not merely tooling

`formal/cubical/theorems/residue/CorpusCalculus.agda` defines, for a point `s = (A , a)`,

```
Question s = Σ[ B ∈ Type ℓ ] (fst s → B)
target s (B , f) = B , f (snd s)
```

so a question is literally **any map out of the object**. The continuing process answers definitionally:

```
respond (run s) q = target s q , refl , run (target s q)
```

`CorpusFinalPresentation.agda` presents the whole checked corpus as the guarded interactive coalgebra with target + exact residual fibre + continuation. `run-corpus-calculus` describes the presentation explicitly as “every question answered on demand with target + exact residual fibre + continuation.”

Thus for SAT, do not ask “what external invariant might measure hardness?” Form the complete Boolean constraint object and ask maps out of it: satisfiability, witness, exact residual, cost/geodesic, normalization, composition, etc. Continue from the returned object.

## SAT object, minimally

For `n` Boolean degrees of freedom, the formula is a compact declarative presentation of

```
F : 2^n → 2
```

and search SAT returns a witness in the satisfying fibre; decision SAT is inhabitation/truncation of that fibre. A 3-clause is a local three-coordinate map; negation gives its unique violating codimension-three cell. The whole CNF is composition of those local constraints over literally shared coordinates.

Equivalently in the Boolean quotient algebra,

```
B_n = F₂[x₁,…,x_n] / (xᵢ²-xᵢ)
```

with clause violation indicators `v_α`,

```
F = ∏_α (1 + v_α)
UNSAT ↔ F = 0 in B_n.
```

This is an exact algebraic presentation, not a proposed SAT algorithm.

## Information-theoretic discipline

For an explicit 3CNF, the description is roughly `O(m log n)` bits while the extensional truth table has `2^n` entries. The latter are not `2^n` independent information bits; they are generated by the compact constraint description.

Never infer execution cost from:

- `2^n` assignments,
- truth-table length,
- raw witness-space cardinality,
- cube dimension,
- number of syntactic branches,
- number of intersections,
- a naively expanded polynomial/ANF,
- residual population in one arbitrary coordinate order.

The repo already contains counterexamples/transport results showing that large presentations can collapse under exact factorization/equivalence.

If an exponential geodesic exists, it is a statement about exact **information-transport/composition distance** under the primitive cost semantics, not information creation or endpoint cardinality.

But again: do not now invent an external proxy for that distance. Ask the existing universal machine for the exact object/cost/residual and continue from its returned mathematics.

## Existing SAT derivations worth retaining

The earlier work established useful exact identities:

- violated 3-clauses are codimension-three Boolean cells;
- `F` is UNSAT iff those cells cover the Boolean cube;
- compatible clause intersections are coordinate cells and incompatible intersections are empty;
- `Σ_x ν(x)=m·2^(N-3)`;
- every exactly-three-literal UNSAT CNF has `m ≥ 8`;
- at `m=8`, violation cells partition the cube;
- `Σ_x(ν(x)-1)=(m-8)2^(N-3)` for UNSAT;
- the full factorial-moment/intersection tower gives exact inclusion-exclusion;
- decision and witness are two projections of the same satisfying fibre;
- cardinality is not interaction cost;
- the universal primitive-edge potential law supplies exact lower bounds/geodesic attainment when instantiated.

These are inputs to the machine, not a reason to continue manually inventing “next lemmas.”

## Anti-regression rule

**If you can state the next mathematical question precisely, encode that question and ask the machine.**

Do not write “it remains to prove X” when X can be submitted as a proposition/object now. Do not substitute a speculative research direction for execution. A rejected candidate module is useful data about that proof term/module, not a theorem that the proposition is false; repair/reformulate using the kernel output and continue.

The human request is specifically to exploit the already-built universal executable machinery rather than rediscover lower-level complexity theory by hand.
