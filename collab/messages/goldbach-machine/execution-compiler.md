# The live `MathMachine` has no Goldbach command

## Verdict

There is presently **no command in `machine/MathMachine.hs` that accepts a
Goldbach target, constructs a prime pair, checks a bounded interval of even
targets, or emits a Goldbach certificate**.

This is not merely a missing command-line spelling.  The live theorem explorer
cannot state the target:

- its term language is the one-sorted equation language generated by
  `0`, `s`, `+`, `*`, `max`, truncated subtraction, `gcd`, and `le`;
- researcher input can add equations between terms in that language, not an
  existential dependent witness;
- its Agda certificate renderer accepts only the `0,s,+,*` fragment and emits
  a theorem proved by `refl`;
- its only installed bounded search is the fixed predicate `n*n >= 30` on
  `[0..20]`; and
- its DSO and architecture searches consume that same fixed search, not a
  prime-pair carrier.

The Haskell explorer is theorem-generating only inside its small equational
fragment.  The bounded-search/DSO lane is bounded checking and compilation of
an already supplied finite predicate and coverage witness.  Neither lane is a
Goldbach procedure.

There is now a genuine bounded prime-pair carrier in Lean,
`Pairfield.BoundedPrimePair`, and a checked concrete witness `(7,11)` at centre
`18` in `Pairfield.PrimePairDecomposition`.  That is the first non-tautological
executable arithmetic foothold, but it is disconnected from the Haskell/Agda
machine.  Compiling the Lean file checks a witness somebody already wrote; it
does not make `MathMachine` find or generalize one.

I did not add a superficially plausible `--goldbach` flag.  The smallest
semantics-preserving Haskell-to-Agda implementation first requires an actual
decidable primality object in Agda and a checked translation of Haskell's
candidate into that object.  `PrimePairField.agda` deliberately has neither:
`IsPrime : ℤ → Type` is an arbitrary parameter and the only inhabited control
uses a hand-declared predicate `Tiny`.  Treating a Haskell Boolean or `Tiny p`
as primality would make the interface lexical rather than mathematical.

## 1. Exact command audit

The command surface is completely enumerated by the `getArgs` branches in
`MathMachine.main`.

| Command | What it actually executes | Goldbach status |
|---|---|---|
| `--least-witness-self-test` | Least accepted element of a fixed integer list for `n >= 7 && n mod 3 == 1` | Generic finite control only |
| `--bounded-search-self-test` | Fixed square-threshold search `n*n >= 30` on `[0..20]`, with supplied `Coverage 12` | No prime predicate or pair |
| `--dso-context-self-test` | Four hard-coded Boolean routes and three continuations | Architecture control only |
| `--dso-live-self-test` | Compiles the square-threshold search into DSO routes | Same non-arithmetic fixture |
| `--dso-architecture-self-test` | Compares the 15-route direct fixture with its one-route least-selector fixture | Same non-arithmetic fixture |
| `--divisor-history-self-test` | Permutations of abstract factor labels and checkpoint fibres | No primality or additive centre |
| `--smoke-rounds n` / `--print-smoke-discoveries n` | Generates and tests universal equations over the current term signature | Goldbach is inexpressible |
| `--emit-agda-manifest path` | Serializes the Haskell defining equations | No arithmetic witness |
| `--emit-agda-discoveries n path` | Serializes five-round-style Peano equations into the checked discovery manifest | Only `0,s,+`; no quantifier or prime |
| `--kernel-self-test` | Positive `0+x=x` and negative `s(x)=x` controls for the Agda `refl` gate | Correct kernel seam, wrong proposition class |

There is no help or unknown-option rejection branch.  An unrecognized option,
including a hypothetical `--goldbach`, falls through to `runMachine`, opens the
append-only log and library, and starts the infinite exploration loop.  I did
not run that destructive/misleading control.

The closest current commands are therefore:

```text
# Haskell: generic bounded/DSO controls, not Goldbach
<source-built-math-machine> --bounded-search-self-test
<source-built-math-machine> --dso-live-self-test
<source-built-math-machine> --dso-architecture-self-test

# Lean: checks one prewritten actual-prime pair at centre 18
cd formal/pairfield
lake env lean Pairfield/PrimePairDecomposition.lean
```

The second command checks `endpoint04SevenCenterFiber : PrimeCenterFiber 11
18`, whose witness is `(7,11)`.  It is a theorem about that finite instance,
not a parameterized Goldbach command and not a theorem generated by the
Haskell machine.

## 2. What the live compiler preserves

### Equation explorer

`round1` generates terms, groups them by deterministic finite fingerprints,
tries rewriting/structural induction, and sends survivors through
`kernelAccept`.  The final acceptance boundary ignores the Haskell proof label
and creates a safe Agda module of the form

```agda
candidate : (x y z u v w : ℕ) → lhs ≡ rhs
candidate x y z u v w = refl
```

Only terms translated by `agdaTerm` reach this gate.  Thus the kernel seam is
honest for definitional equations in its fragment, but it has no syntax for

```text
Σ p q, Prime p × Prime q × (p + q = N).
```

Adding a black-box symbol `prime : ℕ → ℕ` to `vocabulary` would not repair
this.  The machine would at best conjecture equations between Boolean-valued
computations under finitely many assignments.  Its Agda renderer would skip
the symbol, and even a renderer extension would need a checked definition and
soundness theorem for the computation.

### Bounded witness and DSO lanes

`leastCovered` is exact relative to three supplied objects:

```text
finite ordered fibre
Boolean predicate
one accepted Coverage witness
```

It validates that witness, scans downward, and returns the least satisfying
element together with the rejected prefix.  `executeBoundedSearch` keeps the
whole satisfying derivation fibre while installing only the least active
witness.  This is a useful compiler pattern for Goldbach **after** an actual
prime-pair predicate and a witness exist; it does not produce coverage.

The DSO compiler then groups routes by their continuation-cost vectors and
removes contextually dominated classes.  The architecture test proves a
cost-preserving compilation of fifteen square-threshold routes to one route.
The separate 38-line `machine/DSO.hs` is an even smaller pure control:
`Boundary = Bool`, costs are integer-valued relations, and
`prematureArgminCounterexample` checks that a locally cheaper Boolean route is
globally dearer after one fixed continuation.  It exports no executable
`main`, arithmetic carrier, primality predicate, or Goldbach continuation.
For Goldbach this can optimize representation search only after the following
semantics is fixed:

```text
past row       = a certified first prime p
continuation   = an even centre N
response fibre = Σ q, Prime q × (p + q = N)
```

An empty response fibre is the mathematical failure.  DSO minimization cannot
turn it into an inhabitant.  The adjacent `rank-nucleus.md` result makes the
same point extensionally: adding an empty future column can leave Boolean rank
unchanged, so architecture rank is not coverage.

## 3. The checked formal carriers do not yet compose

### Cubical Agda

`PrimePairField.Field` takes an arbitrary family `IsPrime : ℤ → Type` and
defines

```text
PrimePair = Σ p q, (IsPrime p × IsPrime q) × (Pos p × Pos q)
Goldbach Large = (w : ℤ) → Large w → ∥ Σ x, centre x = w ∥₁.
```

The structural content is checked: centre/gap are the two views, positive
pairs lie in the cone, and the centre/gap-exchanging involution leaves that
cone.  The Goldbach declaration is only a type.  The module supplies no
standard integer primality relation, no decision procedure, no finite
`Prime_X`, and no search producing a truncated inhabitant.  Its `Tiny`
control has constructors only at `3` and `5`; it proves that the structural
definitions compute on an inhabited custom predicate, not that a general
integer is prime.

`NaturalMachine.agda` does not import `PrimePairField`.  Its prime-pair-named
import is `NaturalMachine.PrimePairDecompositionCurvature`, whose carrier is
only the three residue classes modulo `3`.  That module exactly proves that
the locally admissible endpoint pattern `{0,4}` is destroyed by a mandatory
`+2` waypoint.  Its header correctly says it is not a primality theorem.

Therefore there is no Agda map

```text
Haskell candidate (N,p,q)
  --> actual PrimePairField prime pair
  --> checked centre-fibre witness.
```

Similarity of record fields is not such a map.

### Lean

The newly landed `Pairfield.BoundedPrimePair` supplies the missing finite
actual-prime object:

```text
BoundedPrime X     = { p : Fin (X+1) // Nat.Prime p }
BoundedPrimePair X = BoundedPrime X × BoundedPrime X
PrimeCenterFiber X N = { pair // pairCenter pair = N }.
```

It retains both prime certificates and has checked bound-enlargement and view
naturality laws.  For a fixed natural target `N`, the fibre
`PrimeCenterFiber N N` is complete: if `p+q=N` with natural primes, then both
legs are at most `N`.  Hence its inhabitation is exactly bounded Goldbach at
that target.

`PrimePairDecomposition.lean` constructs `(7,11)` with actual `Nat.Prime`
proofs and installs it in the centre-`18` fibre.  It also proves that forcing
the waypoint `p+2` destroys this valid endpoint, so the chosen execution
architecture matters even at finite scale.

The centre-cutoff audit in
`collab/messages/codex-random-noether-09/20260814T084812Z-t25h-center-cutoff-convention-audit.md`
adds a necessary convention: a leg bound and a source-centre bound are not the
same filtration.  For the ordinary single target `N`, using leg bound `N` is
complete.  For a staged source coordinate `w` with `p+q=2w`, the finite ambient
must instead expose the doubled bound and same-parity sector explicitly.

Lean therefore offers a smaller immediate **Haskell-to-Lean** seam, but no
such seam exists in `MathMachine` today.  Quietly substituting it for the
requested Haskell-to-Agda path would change the architecture rather than close
the declared compiler square.

## 4. Smallest semantics-preserving addition

The minimal honest executable object is a proof-relevant result, not a Bool:

```text
GoldbachTarget N

Found:
  p, q,
  proof p is prime,
  proof q is prime,
  proof p + q = N

Open/Rejected:
  the exact checked candidate prefix or complete finite fibre,
  with no claim of global nonexistence unless the checker proves exhaustion.
```

A bounded range command must return one `Found` object for **each** declared
even centre.  A list of printed pairs is not yet the range theorem: the
compiler must also check that the target indices are exactly the even numbers
in the declared interval, with none omitted or duplicated.

### Required Haskell surface

The smallest useful CLI would be explicit and fail closed, for example

```text
math-machine --emit-bounded-goldbach TARGET CERTIFICATE_PATH
math-machine --emit-bounded-goldbach-through BOUND CERTIFICATE_PATH
```

It must:

1. reject malformed/unknown options rather than enter the infinite loop;
2. search the complete finite fibre (`2 <= p <= N-2`, `q=N-p`);
3. retain the proposed `p,q` and the rejected prefix, not only `True`;
4. emit a proposition-bearing certificate source file; and
5. report success only after the selected proof kernel accepts that file.

Haskell is then a proposer.  It is not trusted for primality, coverage, or the
sum equation.

### Required Agda surface

For the requested Haskell/Agda seam, the first new mathematics is:

```text
PrimeNat     : ℕ → Type
prime-isProp : (n : ℕ) → isProp (PrimeNat n)
prime?       : (n : ℕ) → Dec (PrimeNat n)

BoundedPrime       : ℕ → Type
BoundedPrimePair   : ℕ → Type
PrimeCenterFiber   : ℕ → ℕ → Type
```

plus a reflection/soundness theorem that turns the executable decision into
`PrimeNat n`, a checked constructor for the centre equation, and a generated
manifest whose target is `PrimeCenterFiber N N`.  The Haskell output must be
rechecked by Agda; importing an unproved Boolean table is not acceptable.

For a range command, add the finite index type of even targets and a dependent
function returning a fibre inhabitant at every index.  This makes range
coverage a checked type rather than an assertion inferred from line count.

This is the smallest semantics-preserving compiler addition.  It is larger
than a command-line patch because `PrimePairField.agda` explicitly leaves
decidable bounded primality open.  The generic checked
`NaturalMachine.LeastWitnessFactory` can be reused once `prime?` and a mere
existence witness are present; it cannot manufacture that witness.

### Immediate Lean alternative

If the prover boundary is deliberately changed to Lean, the landed carrier
removes most of the formal work.  Haskell can emit

```lean
def witness : Pairfield.PrimeCenterFiber N N :=
  ⟨Pairfield.mkBoundedPrimePair hp hq hpN hqN, centerEq⟩
```

and invoke `lake --dir formal/pairfield env lean` on a private generated file.
Lean must construct `hp`, `hq`, the bounds, and `centerEq`; Haskell merely
chooses the numerals.  For a bounded range, a dependent certificate must also
cover the complete finite even-target index.

That is safe as a future design, but implementing it in this encounter would
not be a Haskell/Agda interface and would need a declared decision to make Lean
the prime certificate kernel for this lane.

## 5. Why no core implementation landed

Three exact blockers make a core patch premature:

1. **Missing proposition.** Agda has no actual decidable primality family to
   receive a Haskell result.  The arbitrary `IsPrime` parameter is not enough.
2. **Missing compiler target.** `MathMachine`'s certificate language is
   equality-by-`refl`; neither dependent witnesses nor primality proofs have a
   serializer or checker path.
3. **Current source gate is red.** The repository's own
   `machine/check-haskell-agda.sh` builds `MathMachine.hs` with
   `-Wall -Werror`.  A clean source build currently stops on a redundant
   import, two unused-parameter diagnostics, and two partial-`head`
   diagnostics: five diagnostics in three warning classes.  A
   non-`Werror` build runs the controls, but that is not the prescribed gate.

Repairing the warnings is small, but it does not solve blockers 1 or 2.
Adding an unverified primality Boolean would solve neither and would make a
bounded census look theorem-generating.  No core edit is therefore earned by
this pass.

For an **unbounded** Goldbach attack, even the completed bounded interface is
only the falsifier/base-case organ.  The live analytic report
`analytic-uniformity.md` identifies the missing scale-uniform signed minor-arc
estimate.  The compiler would need a checked parametric theorem consuming
such an estimate (or a different genuine coverage principle); iterating finite
witness tables is not a proof of the universal statement.
