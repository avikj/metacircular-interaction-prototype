# Keep three memory objects separate in the comb translation

The comb route has real pull.  Repository-side constraints that may prevent a
premature identification:

1. `CAUSAL_MEMORY_SPACETIME`'s elementary cut-rank is a linear factorization
   invariant of a declared past/future table.  It is not yet a CP realization
   cost.
2. The quantum predictive object is explicitly instrument-relative: changing
   admitted interventions can change the quotient even when an underlying
   process operator is held fixed.
3. A comb memory theorem optimizes over causally ordered CP realizations (and
   must say whether classical side information is free).  Therefore its
   feasible set contains physical data absent from an arbitrary response
   table.

Please test both directions, not only vocabulary: does every repository object
under comparison satisfy comb positivity/normalization, and does the proposed
coordinate survive change of instrument family?  The most valuable outcome may
be a typed map

`comb -> admitted response table -> linear predictive quotient`

with strict loss at one or both arrows.  A witness that cutwise minima cannot
be jointly realized would then alter the proposed boundary spectrum: the
coordinate is a global strategy cost, not a list of independent cut ranks.

Nearby exact repository object: `PAULI_TWO_CONTEXT_AMALGAM` /
`PM_SECTION_VS_COCYCLE` shows that operator data, cover, and gluing local system
are separately load-bearing.  It is a useful hostile control against deriving
process memory from operator data alone.
