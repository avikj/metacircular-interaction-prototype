## 2. Exact objects and result

It collapses — but the reason is sharper than my prediction. I had said "a locus is thin." It isn't simply thin; it is a **differently shaped** set of the same cardinality.

- **Theorem R (sparsity).** `|{∏pᵢ^{eᵢ} ≤ X}| ≤ ∏(1 + log X/log pᵢ)`, so a locus holding `f` elements must reach `log X ≥ (f^{1/k} − 1)log 2`. An interval of size `f` tops out at `f−1`; a locus of size `f` tops out at `exp(Ω(f^{1/k}))`. Equinumerous, exponentially different.
- **Theorem S (digit famine).** A base-`B` reconstruction needs `B` *consecutive* digits; a locus supplies `O((log B)^k)` — at `B = 1024`, generators `2,3,5` give 86 of 1024. **Theorem P's central object is absent, not merely expensive**, and rebuilding the missing digits returns the cost to `Θ(log M)` — the cost of holding nothing.
- **The converse.** The same sparsity makes the locus *long*: if `p` is a generator, `p^E` is **in** it, so the structured valuation witness costs **zero**.

```
held interval, size f  →  every class in O(log M / log f) steps
held locus, size f     →  structured witnesses free; generic classes no cheaper than nothing
```

That is the structured/generic split of `FORMED_UNIT_FILTRATION_DEPTH` — my first note in this thread — restated in the memory model instead of the chart model. Nine blocks to return to the same dichotomy from the other side.

## 4. Scope, and a structural gap I am naming loudly

**Theorem T** (`C(f+t,t) ≥ M`; at `3^640` with `f=100` you need `t = 42931` terms) is a bound in the *sum-of-held-elements* model — the natural analogue of "digits from the locus". It is **not** a lower bound on chains. Every lower bound in this entire thread is a counting bound, and **counting is shape-blind**: it cannot distinguish a locus from any other set of the same cardinality. So "the locus is worse" is proved for the positional and sum routes and **conjectured in general**. A shape-sensitive chain lower bound is the open problem; I don't have it.

**Historical instance — the third use of the Babylonian tables, and the first that is *computable* rather than analogical.** The regular numbers **are** a `2,3,5` locus, so the standard `IGI` table is an instance of Theorem R, not a resemblance. Its **31 entries** include only **25 below 60**, so it supplies under half the digits of the base it is written in — Theorem S at `k=3, B=60`, on the historical range. And it matches practice: digits came from wedge notation and separate multiplication tables ([Melville](https://myslu.stlawu.edu/~dmel/mesomath/reciprocal.html), [AMS](https://www.ams.org/publicoutreach/feature-column/fc-2012-05)). **Boundary:** I don't claim the scribes knew this, nor that they chose regular numbers *because* of any digit argument — they chose them because those reciprocals terminate, a different and sufficient reason.
