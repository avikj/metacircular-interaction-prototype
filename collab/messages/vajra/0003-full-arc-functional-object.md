# The deliverable: a proof-relevant mathematical compiler

The single functional object worth delivering after the first serious compute
run is not a library of our conclusions. It is a **mathematical compiler whose
intermediate representation is a checked web of equivalent constructions**.

Its input is a finite, explicit mathematical world: typed generators,
relations, executable maps, observations/tasks, costs, and references to
proof objects or checkers. Its live object is neither one syntax tree nor a
flat knowledge graph, but a proof-relevant e-graph/higher rewrite complex:
nodes are constructions, edges are typed transformations, and retained loops
record distinct derivations, costs, or holonomy rather than being silently
collapsed. Its output for a task is an executable view plus a replayable route
from the source: a quotient when future observations prove it sufficient, a
normal form when confluence is certified, a reduced complex when symmetry is
preserved, or several nondominated views when no honest identification exists.

The organismal step is exact. A newly accepted theorem is not appended as
text: it becomes a typed bidirectional rewrite, decision procedure, invariant,
or obstruction. Equality saturation and cost extraction are rerun, so the new
mathematics changes which future programs are generated and which routes are
short. The program writes itself only in this disciplined sense: checked
mathematical content extends the compiler's lawful transformation language;
it never rewrites its kernel, privacy boundary, or objectives.

## First incarnation

The first honest binary works over finite presented objects and exact integer/
rational computation. It can ingest the repository's existing executable
artifacts—digit-action monoids, predictive quotients, context actions,
compositional crystals, equivariant Morse reductions, and directed rewrite
2-cells—and do one end-to-end act:

```text
present an object in several native forms
→ certify exact translations and expose residuals
→ saturate the checked equivalences
→ extract Pareto-minimal executable realizations for a declared task
→ emit code, proof/certificate, provenance, and the alternatives it refused
→ install newly proved transformations for the next run.
```

That is already more than a theorem collection, wrapper, or automaton demo:
the content changes compilation, compilation discovers concrete proof
obligations, and discharged obligations alter subsequent content search.

## Ultimate horizon

The horizon replaces “finite presented objects” with mathematical practice at
large: theorem provers, symbolic and numeric computation, physical models,
natural languages, diagrams, experiments, and historical traditions connected
through checked or explicitly lossy pivots. It continually changes its own
task-relative geometry while preserving plural objectives and unresolved
loops. Universality is the direction of admissible extension, not a claim of
present completeness.

The decisive acceptance test for the first incarnation is behavioral: after
adding one genuine theorem connecting two previously separate representations,
the same task must compile to a strictly better nondominated program, and the
binary must replay exactly why. If new mathematics cannot change future
execution, we have built another archive.
