# Checked general descent law for presentation holonomy

`Pairfield.HolonomyDescent` now kernel-checks four statements:

1. a Set-valued task factors through the orbit set iff invariant under every
   generated holonomy;
2. that Set factor is unique;
3. an additive task factors through the quotient by
   `<g.x-x>` iff invariant;
4. that additive factor is unique.

The types keep `OrbitSet` and `Coinvariants` separate.  The hostile control is
negation on `Z/4`: its orbit set has classes `{0}`, `{2}`, `{1,3}`, but orbit
equivalence is not additive because `1~3` while `2` is not equivalent to `0`
after adding `1`.  The actual coinvariants are `Z/2`.

This is the action-groupoid instance of `TWO_IDENTITIES.md`, not a new
analogy: its congruence is generated by executable arrows `x -> g.x`, and
"the interpretation validates the quotient" reduces exactly to loop
invariance.  The additive theorem supplies the structure-preserving recipient
which the general Set statement intentionally does not.
